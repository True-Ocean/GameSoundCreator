## 1. 概要

### 1.1 プロダクト定義

**GameSoundCreator** は、ゲーム向けの BGM および効果音を、**端末内だけで手続き的に生成・試聴・書き出し**できるアプリである。

ユーザーは音楽の専門パラメータではなく、**シーン・用途・雰囲気・長さ**といった制作上の意図を選ぶ。アプリがその意図を内部の生成レシピ（Recipe）に変換し、マッチした音を出す。

- 外部の生成AI API・クラウド推論は使用しない
- オフラインで完結する
- 自作ゲーム用アセット制作ツールとして先に実用化し、その後 App Store で一般向けに販売する

### 1.2 解決する課題

| 課題 | 本製品の答え |
|------|----------------|
| 商用BGM/SEのライセンス費用・探索コスト | 自前生成で量産 |
| AI音楽サービスの通信・課金・利用制限 | 完全ローカル |
| 「ゲームっぽい」短いループとSEの不足 | 用途カタログに特化した意図選択 |
| 音楽知識がないと作れない | ジャンル／シーン／雰囲気の言葉だけで操作 |
| エンジニアが音なしで開発を進められない | 数タップで試聴・書き出し |

### 1.3 非目標（初期リリースではやらないこと）

- 映画級・フルオーケストラの長尺作曲
- 歌声・ボーカル生成
- クラウド同期・マルチユーザー共同編集
- 既存楽曲の解析・模倣（著作権リスク）
- Android 同時リリース（iOS 安定後に再評価）
- あらゆるジャンル×シーンの網羅的・プロ級マッチ（カタログは段階的に拡充）

### 1.4 UX の中核方針

本製品の UI は **DAW（音楽制作ソフト）ではなく、ゲーム用途のカタログ＋ウィザード** である。

```
ジャンル × シーン/用途 × 雰囲気 × 長さ
        ↓
     Intent（意図）
        ↓
 Intent → Recipe マッパー
        ↓
   生成 → 試聴 → 別パターン / 書き出し
```

ユーザーが普段触るのは Intent。BPM・波形名・コード進行などの技術パラメータは「微調整」に隠し、必須操作にしない。

## 2. ユーザーと利用シナリオ

### 2.1 プライマリユーザー（自分）

自作カードバトルアプリ向けに、ジャンル／シーン／用途を選んで BGM・SE を生成し、ファイルとして書き出す。

### 2.2 セカンダリユーザー（App Store 購入者）

インディー開発者・趣味のゲーム制作者が、音楽の専門知識なしに「戦闘BGM」「メニューBGM」「ボタン音」などを作り、他プロジェクトへ書き出す。

### 2.3 主要シナリオ

1. **BGM を意図から作る:** 「BGMスタジオ」→ シーン「プレイ中／バトル」→ 音色・雰囲気 → 長さ「16・起承」→ 再生 → テンポ等を微調整 → 別パターン or 書き出し
2. **SE を意図から作る:** 「効果音スタジオ」→ カテゴリ「カード」→ 用途「ドロー」→ 雰囲気 →（任意でスライダー）→ 再生 → 書き出し
3. **気に入るまで回す:** 同じ画面で「別パターン」（seed 変更）を繰り返し、保存
4. **微調整:** BGMはテンポ／ピッチ／リズム、SEは高さ／音色／強さ／長さ／音数
5. **セット量産（v1 以降）:** 基本セットを一括生成
6. **自作ゲームへ渡す:** 共有シート / Files で WAV をエクスポート

## 4. 意図モデル（Intent）とカタログ

### 4.1 Intent の定義

Intent は、ユーザーが UI 上で選んだ**制作意図**のまとまりである。シリアライズ可能（JSON）とし、ライブラリ保存・共有の単位にもなる。

| フィールド | 型 | 必須 | 説明 |
|------------|-----|------|------|
| `version` | Int | ○ | Intent スキーマ版 |
| `soundType` | Enum | ○ | `bgm` / `sfx` |
| `genreId` | String | ○ | ゲームジャンル |
| `sceneId` | String | BGM時○ | BGM の使用シーン |
| `purposeId` | String | SE時○ | SE の UI／アクション用途 |
| `moodId` | String | ○ | 雰囲気（既定値可） |
| `lengthId` | String | ○ | 長さプリセット（既定値可） |
| `seed` | UInt64? | — | 未指定なら生成時に抽選 |

BGM では `sceneId` を使い `purposeId` は空。SE では `purposeId` を使い `sceneId` は空（または用途から暗示されるシーンを内部保持してもよい）。

#### Intent の JSON 例（BGM）

```json
{
  "version": 1,
  "soundType": "bgm",
  "genreId": "card_battle",
  "sceneId": "battle_normal",
  "moodId": "tense",
  "lengthId": "sec_30",
  "seed": 42
}
```

#### Intent の JSON 例（SE）

```json
{
  "version": 1,
  "soundType": "sfx",
  "genreId": "card_battle",
  "purposeId": "card_draw",
  "moodId": "neutral",
  "lengthId": "sfx_short",
  "seed": 7
}
```

### 4.2 変換パイプライン

```
Intent
  → CatalogLookup（ジャンル／シーン／用途のテンプレ取得）
  → MoodLengthApply（雰囲気・長さを数値に反映）
  → Recipe（エンジン入力）
  → AudioBuffer / File
```

マッパーは App 層ではなく **エンジン隣接の純ロジック**（Swift Package 内）に置き、ユニットテスト可能にする。UI は Intent の組み立てと結果操作に専念する。

### 4.3 ゲームタイプ（`genreId`）

内部互換のために Intent に残す。**BGM スタジオ UI では選択しない**（既定 `card_battle`）。生成時の軽いバイアスにのみ使う。

| ID | 表示名 | UI | 備考 |
|----|--------|----|------|
| `card_battle` | カードバトル | （内部既定） | 既定 |
| `rpg` | RPG | × | ライブラリ互換 |
| `puzzle` | パズル | × | ライブラリ互換 |
| `action` | アクション | × | 準備中 |
| `casual` | カジュアル | × | 準備中 |

### 4.4 BGM シーン（`sceneId`）

シーンは **グループ → 詳細** の2階層で UI に出す（効果音のカテゴリ→用途と同型）。

#### 画面

| ID | 表示名 |
|----|--------|
| `opening` | オープニング |
| `title` | タイトル |
| `menu_main` | メインメニュー |
| `shop` | ショップ |
| `gacha_or_reward` | ガチャ |
| `settings` | 設定 |

#### プレイ中

| ID | 表示名 |
|----|--------|
| `story` | ストーリー |
| `adventure` | 冒険 |
| `explore` | 探索 |
| `battle_normal` | バトル |
| `battle_boss` | ボス戦 |
| `battle_easy` | イージーモード |
| `battle_hard` | ハードモード |
| `battle_extra` | エクストラモード |

（旧 `battle_pinch` はライブラリ互換のため残すが UI 非表示）

#### 結果

| ID | 表示名 |
|----|--------|
| `result_win` | 勝利 |
| `result_lose` | 敗北 |
| `result_happy_end` | ハッピーエンド |
| `result_bad_end` | バッドエンド |

### 4.5 SE 用途（`purposeId`）

用途は **カテゴリ → 用途** の2階層で UI に出す。各用途は専用のエンジンカテゴリを持ち、レトロ合成でも音の作りを分ける。

エンジン内部のカテゴリ ID（例: `sfx.attack.light`）は、マッパーが `purposeId` から解決する。UI は `purposeId` の表示名だけを見せる。

### 4.6 雰囲気（`moodId`）

| ID | 表示名 | Recipe への主な影響 |
|----|--------|---------------------|
| `bright` | 明るい | 長調寄り、高めピッチ、軽い音色 |
| `neutral` | ふつう | 既定テンプレ |
| `tense` | 緊張 | 短調寄り、energy 高め、密度増 |
| `dark` | 暗い | 短調、ローパス、低域強調 |
| `epic` | 壮大 | 同時発音・低域・ファンファーレ要素 |
| `playful` | 軽快 | 高BPM寄り、短い音符、明るいSE |

MVP では UI 上 **3〜5 択**（例: 明るい / ふつう / 緊張 / 暗い）に絞り、他は v1 で追加してよい。

### 4.7 長さ（`lengthId`）

#### BGM

| ID | 表示名 | 目安 |
|----|--------|------|
| `bars_8` | 8小節 | テンポ依存（120BPMなら約16秒） |
| `bars_16` | 16小節 | テンポ依存（120BPMなら約32秒） |
| `bars_24` | 24小節 | テンポ依存（120BPMなら約48秒） |

内部では **4/4 の小節グリッド**でバッファを生成し、コード進行（4小節周期）の倍数でループする。  
厳密な壁時計の秒数一致より、**小節の頭での自然なループ**を優先する。旧ID（`sec_15` 等）は互換のため小節長へマップする。

#### SE

| ID | 表示名 | 目安 |
|----|--------|------|
| `sfx_short` | 短め | 〜200ms 前後（UIクリック系） |
| `sfx_medium` | ふつう | 200–500ms（既定） |
| `sfx_long` | 長め | 500–1500ms（スキル・ジングル） |

用途ごとに既定の `lengthId` を持ち、ユーザー未変更ならそれを使う。

### 4.8 カタログカバレッジ方針

| 段階 | UI | マッパー／エンジン |
|------|-----|-------------------|
| MVP | カードバトル＋主要シーン／用途を選択可能 | 対応テンプレを実装。未対応は出さない |
| v1 | ジャンル・シーンを拡充 | 組み合わせマトリクスを拡張 |
| 販売後 | 「その他」や要望ベースで追加 | 近いテンプレへのフォールバック可 |

**原則:** UI で選べる組み合わせは、必ず生成できること。未実装の組み合わせを選べて失敗する状態は作らない。

## 5. 効果音仕様

### 5.1 エンジンカテゴリと purpose の対応

用途（`purposeId`）はエンジンカテゴリと **1:1**。近い音へのマップはせず、レトロ合成でも用途ごとに作り分ける。

| 系統 | 例 | 作りの要点 |
|------|----|------------|
| UI | タップ／決定／スワイプ／ダブルタップ | クリック・上昇／下降ブリップ・ノイズスイープ・二連クリック |
| カード | ドロー／シャッフル／めくる | 紙擦れ、連打フラッター、スナップ |
| バトル | 斬る／叩く／割る／防御 | 高域ウィップ、低域サンプ、クラック＋破片、金属クラン |
| 魔法 | 炎／氷／毒／回復 | クラックル轟音、ガラス質アルペジオ、泡・うねり、明るいARP |
| 動作 | 歩く／走る／飛ぶ | 足音パルス、空気ウーシュ |
| ガチャ | 回転／レア | 機械ラチェット減速、上昇スパークル＋ファンファーレ |
| 結果 | 勝利／敗北 | 上昇／下降ファンファーレ |

※ 雰囲気（mood）はピッチ／音色／強さの共通変調。長さは `lengthId` で上書き可能。

### 5.2 SE Recipe パラメータ（エンジン入力）

| パラメータ | 型 | 範囲（目安） | 説明 |
|------------|-----|--------------|------|
| `seed` | UInt64 | — | 再現可能な乱数シード |
| `durationMs` | Int | 50–2000 | 長さ（lengthId から設定） |
| `pitch` | Float | 0.5–2.0 | 基準ピッチ倍率 |
| `timbre` | Float | 0–1 | 音色（ノイズ寄り↔トーン寄り） |
| `intensity` | Float | 0–1 | 強さ・歪み・音量エンベロープ |
| `variation` | Int | 0–7 | 同一カテゴリ内の型違い |

出力: モノラルまたはステレオ、サンプルレート **44100 Hz** または **48000 Hz**（アプリ設定で固定、初期は 44100）。

## 6. BGM 仕様

### 6.1 位置づけと音質ゴール

「名曲」や映画級ではなく、**ループ可能な伴奏＋覚えられるメロディ**でゲームに置ける音を出す。

当面の品質目標は **レトロゲーム BGM レベル**（おおよそ 16ビット〜初期インディー）。  
品質は次の **二軸** で上げる（詳細は [SOUND_PLAN.md](SOUND_PLAN.md)）。

| 軸 | 内容 | Phase |
|----|------|-------|
| 音色・空間 | 楽器差・フィルタ・短い残響・簡易FM | 3.5-C / 3.5-D（✅） |
| 作曲・メロディ | モチーフ・リズム型・音高輪郭（人間らしい手続き生成） | 3.5-M |

非目標: フルオーケストラ、商用サンプル並みのリアルさ、外部生成AI、「名曲」の保証。

### 6.2 シーンと初期テンプレ

既存プリセット（`menu_main` / `battle_normal`）をベースに、シーンごとにテンポ・エネルギー等を変調する。

| sceneId | ムード既定 | ベースプリセット |
|---------|------------|------------------|
| `opening` / `title` / `menu_main` / `settings` / `shop` / `story` | bright〜neutral | `bgm.menu.main` |
| `adventure` / `explore` | neutral | `bgm.menu.main` |
| `battle_normal` / `battle_boss` / `battle_easy` / `battle_hard` / `battle_extra` | tense〜neutral | `bgm.battle.normal` |
| `gacha_or_reward` / `result_win` / `result_happy_end` | bright | `bgm.menu.main` |
| `result_lose` / `result_bad_end` | dark | `bgm.battle.normal` |

### 6.3 BGM Recipe パラメータ（エンジン入力）

| パラメータ | 型 | 範囲（目安） | 説明 |
|------------|-----|--------------|------|
| `seed` | UInt64 | — | 再現性 |
| `tempoBpm` | Int | 80–160 | テンポ（UI: テンポ） |
| `key` | Enum | C, D, … / major\|minor | 調性 |
| `bars` | Int | 4–32 | 尺＋展開（8=くり返し／16=起承／24=起承転結） |
| `pitchSemitones` | Int | −6…+6 | 移調（UI: ピッチ） |
| `rhythm` | Float | 0–1 | ドラム／刻みの疎密（UI: リズム） |
| `density` | Float | 0–1 | シーン／雰囲気由来の内部密度 |
| `energy` | Float | 0–1 | シーン／雰囲気由来の内部エネルギー |
| `brightness` | Float | 0–1 | 雰囲気由来（UIなし） |
| `melody` | Bool | — | メロディレイヤー有無 |

### 6.4 音楽構造（エンジン内部）

1. **コード進行テンプレート**（ジャンル／シーン固定の数パターンから seed で選択）
2. **ドラムパターン**（キック / スネア / ハットの簡易シーケンス）
3. **ベース**（ルート＋簡単な歩行）
4. **パッド or コードスタブ**
5. **メロディ**（`MelodyComposer`：モチーフ＋リズム型＋輪郭。長さで展開が変わる）
   - 8小節: くり返し（モチーフ反復）
   - 16小節: 起承（A→対照的なB）
   - 24小節: 起承転結（A→発展→対照→収束）
6. **ループクロスフェード**（書き出し時に継ぎ目を平滑化）

音色はソフトシンセ（サイン／矩形／ノイズ／簡易FM 等）と **楽器プリセット**（ピアノ風・パッド等）で差別化する。  
品質向上時に小さな自作／商用可サンプルバンクの同梱を再評価する（必須ではない）。

### 6.5 音色（instrument）— Phase 3.5

スタジオで選択可能（BGM優先）:

| ID | 表示名 | 備考 |
|----|--------|------|
| `lead_synth` | シンセリード | 戦闘メロディ向き |
| `piano` | ピアノ風 | メニュー向き |
| `pad` | パッド | 雰囲気・敗北寄り |
| `bass` | ベース | 低音前面 |
| `music_box` | オルゴール | 高域プラック。ショップ・ガチャ既定 |
| `organ` | オルガン | 持続・荘厳。ストーリー既定 |
| `guitar` | ギター風 | 明るめプラック。冒険既定 |

Intent の `instrumentId` を Mapper 経由で Recipe に渡す。シーン未指定時は上表の既定を使う。

### 6.6 メロディ作曲（人間らしい手続き生成）— Phase 3.5-M

#### 目的

別パターン（seed 変更）でも「同じランダム連打」に聞こえないこと。  
ゲームBGMとして **短い覚えられる塊** があること。

#### 本製品での「人間らしさ」

| 要素 | 要件 |
|------|------|
| モチーフ | 2〜4小節の形を先に生成し、反復または軽い変奏 |
| リズム型 | 休符・シンコペを含む型のプールから seed で選択 |
| 音高輪郭 | 上昇→頂点→下降、または問い（上行）と答え（下行） |
| ハーモニー | 拍頭はコードトーン中心。あいだにスケール内の経過音可 |
| 抑揚 | フレーズ頭をやや長く／強く、終わりを短く（第一弾から軽く入れる） |

#### アーキテクチャ要件

- `MelodyComposer`（名称は実装時に確定可）を **エンジン隣接の純ロジック**として置き、ユニットテスト可能にする
- 生成結果はノート列（相対度数・開始ステップ・長さ・強さ）とし、`BGMEngine` はそれを再生する
- **UIに作曲用の専門パラメータを増やさない**（既存の seed／雰囲気／密度／音色で効かせる）
- 同一 Intent＋seed なら同一ノート列（再現性）

#### 段階

| Step | 内容 |
|------|------|
| 3.5-M1 | モチーフ＋リズム型＋輪郭（✅ 実装済み） |
| 3.5-M2 | コール＆レスポンス／フィル等（任意・フィードバック次第） |

詳細な実装順・成功指標は [SOUND_PLAN.md](SOUND_PLAN.md) を正とする。

## 7. エンジンアーキテクチャ

### 7.1 論理構成

```
┌──────────────────────────────────────────────┐
│  App (SwiftUI)                               │
│  ホーム / スタジオ / ライブラリ / 設定         │
└─────────────────┬────────────────────────────┘
                  │ Intent
┌─────────────────▼────────────────────────────┐
│  Intent Mapper                               │
│  Catalog + Mood/Length → Recipe              │
└─────────────────┬────────────────────────────┘
                  │ Recipe
┌─────────────────▼────────────────────────────┐
│  Generation Service                          │
│  Recipe → AudioBuffer / File                 │
└─────────────────┬────────────────────────────┘
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
┌───────────────┐   ┌───────────────────────────┐
│ SFX Engine    │   │ BGM Engine                │
│ 合成グラフ    │   │ シーケンサ                │
└───────┬───────┘   │  + MelodyComposer（ノート列）│
        │           └─────────────┬─────────────┘
        └─────────────┬───────────┘
                      ▼
┌──────────────────────────────────────────────┐
│  Audio Runtime (AVAudioEngine)               │
│  再生 / 書き出し (AVAudioFile)               │
└──────────────────────────────────────────────┘
```

### 7.2 レシピ（Recipe）形式

生成エンジンへの入力はすべてシリアライズ可能な **Recipe** とする（JSON）。Intent を保存する場合は、可能なら **Intent と解決済み Recipe の両方**（または Intent＋seed のみ）を残し、カタログ更新後の再現方針をバージョンで管理する。

目的:

- 同じ Recipe から同一音を再生成できる
- 自作カードバトル側に「どのイベントがどの音か」を記録できる
- UI を差し替えてもエンジン資産を保てる

```json
{
  "version": 1,
  "type": "sfx",
  "category": "sfx.attack.light",
  "sourceIntent": {
    "genreId": "card_battle",
    "purposeId": "attack_light",
    "moodId": "tense",
    "lengthId": "sfx_medium"
  },
  "params": {
    "seed": 42,
    "durationMs": 220,
    "pitch": 1.0,
    "timbre": 0.4,
    "intensity": 0.7,
    "variation": 2
  }
}
```

```
App/                      … SwiftUI（ウィザード・結果・ライブラリ）
Sources/AudioGenCore      … 生成エンジン（Swift Package）
  Intent/                 … Intent モデル、Catalog、Mapper
  SFX/
  BGM/
  Render/
  Models/                 … Recipe 等
```

## 8. UI / UX 要件

### 8.1 デザイン原則

| 原則 | 内容 |
|------|------|
| ゲームの言葉で話す | シーン・用途・ボタン・ドローなど。BPMや波形名は出さない |
| 条件はスタジオで揃える | ホームはスタジオ入口のみ。BGM／SEとも1画面インライン（グループ→詳細） |
| 再生ですぐ聴ける | 再生ボタンが未生成ならその場で生成して再生。「生成して聴く」は置かない |
| 起動はオープニング演出 | © → ブランドロゴ → タイトル＋進捗のあとホーム。音声は裏でウォームアップ |
| BGM生成は明示フィードバック | BGM再生成中は「BGM生成中…」を表示（非同期生成） |
| 微調整は主役のひとつ | BGMのテンポ・ピッチ・リズムは再生中でも裏生成して切替。シーン／音色／長さは停止して再生待ち |
| カタログは1画面 | BGM・SEともモーダルなし。スクロール不要を目標 |
| 共有はナビから | 保存・WAV書き出しは右上の共有メニュー |
| BGM と SE を入口で分離 | 長さ・ループの意味が異なるため混在させない |
| 見た目は設定で切替 | テーマカラー: ライム（既定）／アンバー／シアン／マゼンタ／ランダム（起動時に抽選）。選択は端末に保存 |

### 8.2 画面構成

| 画面 | 内容 |
|------|------|
| ホーム | BGMスタジオ / 効果音スタジオ |
| 制作（スタジオ） | 条件（インライン）／微調整／再生・別パターン／共有。スクロール不要を目標 |
| ライブラリ | 再生中心。行タップで制作画面へ。左上「削除」で明示的な削除モード。スワイプ／長押しでも削除 |
| 設定 | テーマカラー切替（ライム／アンバー／シアン／マゼンタ／ランダム）、アプリ情報 |

### 8.3 制作画面詳細

#### 上部 — 再生

- **BGM / SE:** 再生と別パターンを画面最下部に横並び。再生中は再生ボタンが停止に切替
- **BGM:** 進捗バー、ループ／メロディトグル
- 再生は未生成・条件dirtyなら再生成してから鳴らす
- **別パターン**で seed 変更して再生成

#### 微調整（インライン）

- SE: 高さ／音色／強さ／長さ／音数（設定変更では鳴らさず、再生／別パターンで反映）
- BGM: テンポ／ピッチ／リズム／メロディは再生中でも旧音を継続しつつ再生成し、完了後に切替（「BGM生成中…」）
- BGM: シーン／詳細／音色／長さ（展開）の変更は再生を停止し、再生ボタンで確定
- BGM: ループは再生成なしで即反映
- 明るさは雰囲気から内部設定（UIスライダーなし）

#### 条件

- BGM・SEとも制作画面にインライン配置（モーダルなし）。スクロール不要を目標
- BGM: シーン（画面／プレイ中／結果）→ 詳細、音色、雰囲気、長さ・展開。`genreId` は内部既定
- BGM長さ: `8・繰返`／`16・起承`／`24・転結`（尺に加えメロディ・アレンジの区間展開）
- SE: カテゴリ → 用途、雰囲気。カタログ変更は再生／別パターンまで鳴らさない
- シーン変更時は雰囲気・長さ・音色の既定を更新

#### 共有（ナビ右上）

- ライブラリに保存
- WAVを書き出して共有

### 8.4 画面遷移（概要）

```
ホーム
  ├─ BGM ─→ 制作画面（シーン2階層・1画面）
  └─ SE  ─→ 制作画面（カテゴリ → 用途・1画面）
ライブラリ → 制作画面
制作 → 共有メニュー（保存／WAV）
```

### 8.5 アクセシビリティ

- Dynamic Type 対応
- 主要な操作に VoiceOver ラベル（「再生」「別パターン」「共有」等）
- 再生中は視覚的インジケータを表示
- 色だけに依存しない選択状態（チェックや太枠など）

### 8.6 空状態・エラー

| 状況 | 振る舞い |
|------|----------|
| 初回起動 | ホームで2択を強調。説明は短文1行まで |
| 生成失敗 | 再試行ボタン。技術詳細は折りたたみ |
| 書き出し失敗 | 権限・空き容量を平易に案内 |
| カタログ準備中 | 選択不可＋「準備中」 |

## 14. リスクと対策

| リスク | 対策 |
|--------|------|
| 音が「おもちゃ」に聞こえる | プリセット調整と簡易マスタリングを早めに入れる |
| BGM メロディがランダム連打に聞こえる | MelodyComposer（モチーフ＋リズム型＋輪郭）。詳細は SOUND_PLAN |
| BGM のループ継ぎ目が目立つ | 小節単位設計＋クロスフェード書き出し |
| ジャンル追加が UI だけ先行する | 「選べる＝実装済み」ルールとカタログ単一ソース |
| 選択肢が多すぎて迷う | MVPは少数。グループ化。既定値を強くする |
| 開発が UI に偏りエンジンが育たない | Phase 1–2 で Mapper＋エンジンを先に固める。3.5 もエンジン中心 |
| ストアでAIアプリと誤認 | 手続き生成である旨を説明文・アプリ内に明記 |
| サンプル音源の権利 | 初期は合成のみ。追加時はライセンス表を必須化 |

## 15. 用語集

| 用語 | 意味 |
|------|------|
| 手続き的生成 | 乱数とルールで波形・音符を組み立てる方式。学習モデル必須ではない |
| Intent | ジャンル・シーン／用途・雰囲気・長さなど、ユーザーが選んだ制作意図 |
| Catalog | ジャンル／シーン／用途などの選択肢と、それに紐づく生成テンプレの定義集合 |
| Mapper | Intent を Recipe に変換する純ロジック |
| Recipe | エンジンが音を生成するために必要なパラメータ一式 |
| シード | 乱数の初期値。同じ Intent＋シードなら同じ結果を目指す |
| 別パターン | seed を変え、同じ意図のまま別バリエーションを生成する操作 |
| モチーフ | 反復・変奏の単位となる短いメロディ形（本製品ではおおむね2〜4小節） |
| MelodyComposer | Intent／Recipe からノート列を組み立てる純ロジック。長さに応じた展開（くり返し／起承／起承転結）を含む |
| ループBGM | 終端と始端が自然につながるよう設計された伴奏 |
| 微調整 | 制作画面インラインのテンポ・ピッチ・リズム等（BGM）／高さ・音色等（SE） |
