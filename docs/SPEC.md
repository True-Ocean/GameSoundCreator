## 1. 概要

### 1.1 プロダクト定義

**GameSoundCreator** は、ゲーム向けの BGM および効果音を、**端末内だけで手続き的に生成・試聴・書き出し**できるアプリである。

ユーザーは音楽の専門パラメータではなく、**ゲームジャンル・シーン・UI/アクション用途・長さ・雰囲気**といった制作上の意図を選ぶ。アプリがその意図を内部の生成レシピ（Recipe）に変換し、マッチした音を出す。

- 外部の生成AI API・クラウド推論は使用しない
- オフラインで完結する
- 自作ゲーム用アセット制作ツールとして先に実用化し、その後 App Store で一般向けに販売する

### 1.2 解決する課題

| 課題 | 本製品の答え |
|------|----------------|
| 商用BGM/SEのライセンス費用・探索コスト | 自前生成で量産 |
| AI音楽サービスの通信・課金・利用制限 | 完全ローカル |
| 「ゲームっぽい」短いループとSEの不足 | 用途カタログに特化した意図選択 |
| 音楽知識がないと作れない | ジャンル／シーン／雰囲気の言葉だけで操作 |
| エンジニアが音なしで開発を進められない | 数タップで試聴・書き出し |

### 1.3 非目標（初期リリースではやらないこと）

- 映画級・フルオーケストラの長尺作曲
- 歌声・ボーカル生成
- クラウド同期・マルチユーザー共同編集
- 既存楽曲の解析・模倣（著作権リスク）
- Android 同時リリース（iOS 安定後に再評価）
- あらゆるジャンル×シーンの網羅的・プロ級マッチ（カタログは段階的に拡充）

### 1.4 UX の中核方針

本製品の UI は **DAW（音楽制作ソフト）ではなく、ゲーム用途のカタログ＋ウィザード** である。

```
ジャンル × シーン/用途 × 雰囲気 × 長さ
        ↓
     Intent（意図）
        ↓
 Intent → Recipe マッパー
        ↓
   生成 → 試聴 → 別パターン / 書き出し
```

ユーザーが普段触るのは Intent。BPM・波形名・コード進行などの技術パラメータは「微調整」に隠し、必須操作にしない。

## 2. ユーザーと利用シナリオ

### 2.1 プライマリユーザー（自分）

自作カードバトルアプリ向けに、ジャンル／シーン／用途を選んで BGM・SE を生成し、ファイルとして書き出す。

### 2.2 セカンダリユーザー（App Store 購入者）

インディー開発者・趣味のゲーム制作者が、音楽の専門知識なしに「戦闘BGM」「メニューBGM」「ボタン音」などを作り、他プロジェクトへ書き出す。

### 2.3 主要シナリオ

1. **BGM を意図から作る:** 「BGM」→ ジャンル「カードバトル」→ シーン「戦闘」→ 雰囲気「緊張め」→ 長さ「30秒」→ 生成して聴く → 別パターン or 書き出し
2. **SE を意図から作る:** 「効果音」→ ジャンル → 用途「カードをドロー」→ 雰囲気／長さ（任意）→ 生成 → 書き出し
3. **気に入るまで回す:** 結果画面で「別パターン」（seed 変更）を繰り返し、保存
4. **微調整（任意）:** 詳細スライダーでピッチや energy などを調整（上級者向け）
5. **セット量産（v1 以降）:** ジャンルの基本セットを一括生成
6. **自作ゲームへ渡す:** 共有シート / Files で WAV または AAC をエクスポート

## 4. 意図モデル（Intent）とカタログ

### 4.1 Intent の定義

Intent は、ユーザーが UI 上で選んだ**制作意図**のまとまりである。シリアライズ可能（JSON）とし、ライブラリ保存・共有の単位にもなる。

| フィールド | 型 | 必須 | 説明 |
|------------|-----|------|------|
| `version` | Int | ○ | Intent スキーマ版 |
| `soundType` | Enum | ○ | `bgm` / `sfx` |
| `genreId` | String | ○ | ゲームジャンル |
| `sceneId` | String | BGM時○ | BGM の使用シーン |
| `purposeId` | String | SE時○ | SE の UI／アクション用途 |
| `moodId` | String | ○ | 雰囲気（既定値可） |
| `lengthId` | String | ○ | 長さプリセット（既定値可） |
| `seed` | UInt64? | — | 未指定なら生成時に抽選 |

BGM では `sceneId` を使い `purposeId` は空。SE では `purposeId` を使い `sceneId` は空（または用途から暗示されるシーンを内部保持してもよい）。

#### Intent の JSON 例（BGM）

```json
{
  "version": 1,
  "soundType": "bgm",
  "genreId": "card_battle",
  "sceneId": "battle_normal",
  "moodId": "tense",
  "lengthId": "sec_30",
  "seed": 42
}
```

#### Intent の JSON 例（SE）

```json
{
  "version": 1,
  "soundType": "sfx",
  "genreId": "card_battle",
  "purposeId": "card_draw",
  "moodId": "neutral",
  "lengthId": "sfx_short",
  "seed": 7
}
```

### 4.2 変換パイプライン

```
Intent
  → CatalogLookup（ジャンル／シーン／用途のテンプレ取得）
  → MoodLengthApply（雰囲気・長さを数値に反映）
  → Recipe（エンジン入力）
  → AudioBuffer / File
```

マッパーは App 層ではなく **エンジン隣接の純ロジック**（Swift Package 内）に置き、ユニットテスト可能にする。UI は Intent の組み立てと結果操作に専念する。

UI ではチップ／グリッドで選択。MVP では `card_battle` 以外は非表示、または「準備中」表示。

### 4.6 雰囲気（`moodId`）

| ID | 表示名 | Recipe への主な影響 |
|----|--------|---------------------|
| `bright` | 明るい | 長調寄り、高めピッチ、軽い音色 |
| `neutral` | ふつう | 既定テンプレ |
| `tense` | 緊張 | 短調寄り、energy 高め、密度増 |
| `dark` | 暗い | 短調、ローパス、低域強調 |
| `epic` | 壮大 | 同時発音・低域・ファンファーレ要素 |
| `playful` | 軽快 | 高BPM寄り、短い音符、明るいSE |

MVP では UI 上 **3〜5 択**（例: 明るい / ふつう / 緊張 / 暗い）に絞り、他は v1 で追加してよい。

### 4.7 長さ（`lengthId`）

#### BGM

| ID | 表示名 | 目安 |
|----|--------|------|
| `bars_8` | 8小節 | テンポ依存（120BPMなら約16秒） |
| `bars_16` | 16小節 | テンポ依存（120BPMなら約32秒） |
| `bars_24` | 24小節 | テンポ依存（120BPMなら約48秒） |

内部では **4/4 の小節グリッド**でバッファを生成し、コード進行（4小節周期）の倍数でループする。  
厳密な壁時計の秒数一致より、**小節の頭での自然なループ**を優先する。旧ID（`sec_15` 等）は互換のため小節長へマップする。

#### SE

| ID | 表示名 | 目安 |
|----|--------|------|
| `sfx_short` | 短め | 〜200ms 前後（UIクリック系） |
| `sfx_medium` | ふつう | 200–500ms（既定） |
| `sfx_long` | 長め | 500–1500ms（スキル・ジングル） |

用途ごとに既定の `lengthId` を持ち、ユーザー未変更ならそれを使う。

### 4.8 カタログカバレッジ方針

| 段階 | UI | マッパー／エンジン |
|------|-----|-------------------|
| MVP | カードバトル＋主要シーン／用途を選択可能 | 対応テンプレを実装。未対応は出さない |
| v1 | ジャンル・シーンを拡充 | 組み合わせマトリクスを拡張 |
| 販売後 | 「その他」や要望ベースで追加 | 近いテンプレへのフォールバック可 |

**原則:** UI で選べる組み合わせは、必ず生成できること。未実装の組み合わせを選べて失敗する状態は作らない。

## 6. BGM 仕様

### 6.1 位置づけと音質ゴール

「名曲」や映画級ではなく、**ループ可能な伴奏＋覚えられるメロディ**でゲームに置ける音を出す。

当面の品質目標は **レトロゲーム BGM レベル**（おおよそ 16ビット〜初期インディー）。  
品質は次の **二軸** で上げる（詳細は [SOUND_PLAN.md](SOUND_PLAN.md)）。

| 軸 | 内容 | Phase |
|----|------|-------|
| 音色・空間 | 楽器差・フィルタ・短い残響・簡易FM | 3.5-C（✅） / 3.5-D |
| 作曲・メロディ | モチーフ・リズム型・音高輪郭（人間らしい手続き生成） | 3.5-M |

非目標: フルオーケストラ、商用サンプル並みのリアルさ、外部生成AI、「名曲」の保証。

### 6.2 シーンと初期テンプレ（カードバトル）
| sceneId | 目安長さ | ムード既定 | 内部テンプレ（例） |
|---------|----------|------------|-------------------|
| `battle_normal` | 16–32 秒 | `tense` | `bgm.battle.normal` |
| `menu_main` | 20–40 秒 | `bright` / `neutral` | `bgm.menu.main` |
| `result_win` | 短い〜中 | `bright` | `bgm.result.win`（短ループまたはワンショット寄り） |
| `result_lose` | 短い〜中 | `dark` | `bgm.result.lose` |

### 6.3 BGM Recipe パラメータ（エンジン入力）

| パラメータ | 型 | 範囲（目安） | 説明 |
|------------|-----|--------------|------|
| `seed` | UInt64 | — | 再現性 |
| `tempoBpm` | Int | 80–160 | テンポ（ジャンル・シーン・mood から推奨帯） |
| `key` | Enum | C, D, … / major\|minor | 調性 |
| `bars` | Int | 4–32 | ループ小節数（lengthId から） |
| `density` | Float | 0–1 | 音符の密度 |
| `energy` | Float | 0–1 | ドラム・低域の強さ |
| `melody` | Bool | — | メロディレイヤー有無 |

### 6.4 音楽構造（エンジン内部）

1. **コード進行テンプレート**（ジャンル／シーン固定の数パターンから seed で選択）
2. **ドラムパターン**（キック / スネア / ハットの簡易シーケンス）
3. **ベース**（ルート＋簡単な歩行）
4. **パッド or コードスタブ**
5. **メロディ**（下記 6.6。スケール内のステップ独立ランダムは廃止予定）
6. **ループクロスフェード**（書き出し時に継ぎ目を平滑化）

音色はソフトシンセ（サイン／矩形／ノイズ／簡易FM 等）と **楽器プリセット**（ピアノ風・パッド等）で差別化する。  
品質向上時に小さな自作／商用可サンプルバンクの同梱を再評価する（必須ではない）。

### 6.5 音色（instrument）— Phase 3.5

スタジオで選択可能（BGM優先）:

| ID | 表示名 | 優先 |
|----|--------|------|
| `lead_synth` | シンセリード | 必須（実装済み） |
| `piano` | ピアノ風 | 必須（実装済み） |
| `pad` | パッド／ストリングス風 | 必須（実装済み） |
| `bass` | ベース | 必須（実装済み） |
| `organ` | オルガン風 | 任意 |
| `guitar` | ギター風 | 任意 |

Intent の `instrumentId` を Mapper 経由で Recipe に渡す。

### 6.6 メロディ作曲（人間らしい手続き生成）— Phase 3.5-M

#### 目的

別パターン（seed 変更）でも「同じランダム連打」に聞こえないこと。  
ゲームBGMとして **短い覚えられる塊** があること。

#### 本製品での「人間らしさ」

| 要素 | 要件 |
|------|------|
| モチーフ | 2〜4小節の形を先に生成し、反復または軽い変奏 |
| リズム型 | 休符・シンコペを含む型のプールから seed で選択 |
| 音高輪郭 | 上昇→頂点→下降、または問い（上行）と答え（下行） |
| ハーモニー | 拍頭はコードトーン中心。あいだにスケール内の経過音可 |
| 抑揚 | フレーズ頭をやや長く／強く、終わりを短く（第一弾から軽く入れる） |

#### アーキテクチャ要件

- `MelodyComposer`（名称は実装時に確定可）を **エンジン隣接の純ロジック**として置き、ユニットテスト可能にする
- 生成結果はノート列（相対度数・開始ステップ・長さ・強さ）とし、`BGMEngine` はそれを再生する
- **UIに作曲用の専門パラメータを増やさない**（既存の seed／雰囲気／密度／音色で効かせる）
- 同一 Intent＋seed なら同一ノート列（再現性）

#### 段階

| Step | 内容 |
|------|------|
| 3.5-M1 | モチーフ＋リズム型＋輪郭（必須） |
| 3.5-M2 | コール＆レスポンス／フィル等（任意・フィードバック次第） |

詳細な実装順・成功指標は [SOUND_PLAN.md](SOUND_PLAN.md) を正とする。

## 7. エンジンアーキテクチャ

### 7.1 論理構成

```
┌──────────────────────────────────────────────┐
│  App (SwiftUI)                               │
│  ホーム / スタジオ / ライブラリ / 設定         │
└─────────────────┬────────────────────────────┘
                  │ Intent
┌─────────────────▼────────────────────────────┐
│  Intent Mapper                               │
│  Catalog + Mood/Length → Recipe              │
└─────────────────┬────────────────────────────┘
                  │ Recipe
┌─────────────────▼────────────────────────────┐
│  Generation Service                          │
│  Recipe → AudioBuffer / File                 │
└─────────────────┬────────────────────────────┘
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
┌───────────────┐   ┌───────────────────────────┐
│ SFX Engine    │   │ BGM Engine                │
│ 合成グラフ    │   │ シーケンサ                │
└───────┬───────┘   │  + MelodyComposer（ノート列）│
        │           └─────────────┬─────────────┘
        └─────────────┬───────────┘
                      ▼
┌──────────────────────────────────────────────┐
│  Audio Runtime (AVAudioEngine)               │
│  再生 / 書き出し (AVAudioFile)               │
└──────────────────────────────────────────────┘
```

### 7.2 レシピ（Recipe）形式

生成エンジンへの入力はすべてシリアライズ可能な **Recipe** とする（JSON）。Intent を保存する場合は、可能なら **Intent と解決済み Recipe の両方**（または Intent＋seed のみ）を残し、カタログ更新後の再現方針をバージョンで管理する。

目的:

- 同じ Recipe から同一音を再生成できる
- 自作カードバトル側に「どのイベントがどの音か」を記録できる
- UI を差し替えてもエンジン資産を保てる

```json
{
  "version": 1,
  "type": "sfx",
  "category": "sfx.attack.light",
  "sourceIntent": {
    "genreId": "card_battle",
    "purposeId": "attack_light",
    "moodId": "tense",
    "lengthId": "sfx_medium"
  },
  "params": {
    "seed": 42,
    "durationMs": 220,
    "pitch": 1.0,
    "timbre": 0.4,
    "intensity": 0.7,
    "variation": 2
  }
}
```

### 7.3 モジュール境界（推奨ディレクトリ）

```
App/                      … SwiftUI（ウィザード・結果・ライブラリ）
Sources/AudioGenCore      … 生成エンジン（Swift Package）
  Intent/                 … Intent モデル、Catalog、Mapper
  SFX/
  BGM/
  Render/
  Models/                 … Recipe 等
```

## 8. UI / UX 要件

### 8.1 デザイン原則

| 原則 | 内容 |
|------|------|
| ゲームの言葉で話す | ジャンル・シーン・ボタン・ドローなど。BPMや波形名は出さない |
| ジャンルは入口で決める | ホームでジャンルをメニュー選択。制作画面はその前提で条件だけ |
| 再生ですぐ聴ける | 再生ボタンが未生成ならその場で生成して再生。「生成して聴く」は置かない |
| 微調整は主役のひとつ | 再生直下に常時表示し、変更はほぼリアルタイム反映（BGMは短い debounce） |
| カタログは明示適用 | 条件は中央フロートで編集し、「反映して再生」で初めて確定・再生成する |
| 共有はナビから | 保存・WAV書き出しは右上の共有メニュー |
| BGM と SE を入口で分離 | 長さ・ループの意味が異なるため混在させない |
| 見た目は設定で切替 | 標準／アンバー／CRT緑／シアン。選択は端末に保存 |

### 8.2 画面構成

| 画面 | 内容 |
|------|------|
| ホーム | ジャンル（メニュー）＋ BGMスタジオ / 効果音スタジオ |
| 制作（スタジオ） | 生成条件（最上段・フロート編集）／再生／微調整／別パターン／共有 |
| ライブラリ | 再生中心。行タップで制作画面へ。左上「削除」で明示的な削除モード。スワイプ／長押しでも削除 |
| 設定 | テーマ切替（標準／アンバー／CRT緑／シアン）、アプリ情報 |

### 8.3 制作画面詳細

#### 上部 — 再生

- **BGM:** 再生バー、再生／停止、ループ
- **効果音:** 再生のみ（短いワンショットのためバー・停止は出さない）
- 再生は条件が変わっていれば再生成してから鳴らす
- **別パターン**で seed 変更して再生成

#### 微調整（インライン）

- SE: 高さ／音色／強さ（変更は debounce 後に即再適用）
- BGM: 速さ／迫力／密度／メロディ
- スライダー変更は debounce 後に即再適用・再生（適用ボタンなし）

#### 条件

- 条件バーから **中央フロート** を開く（背景タップやスワイプでは閉じない）
- 編集は下書き。**「反映して再生」** で本番条件にコピーして再生成・再生し、フロートを閉じる
- **「キャンセル」** で下書き破棄（音は変えない）
- シーン・音色・用途はフロート内の一覧で選択（SE用途はカテゴリ見出し付き）
- 雰囲気・長さはセグメント
- ジャンルは制作画面に出さない（ホームで確定済み）

#### 共有（ナビ右上）

- ライブラリに保存
- WAVを書き出して共有

### 8.4 画面遷移（概要）

```
ホーム（ジャンル）
  ├─ BGM ─→ 制作画面
  └─ SE  ─→ 制作画面
ライブラリ → 制作画面
制作 → 条件フロート（下書き）→ 反映して再生 → 制作
制作 → 共有メニュー（保存／WAV）
```

### 8.5 アクセシビリティ

- Dynamic Type 対応
- 主要な操作に VoiceOver ラベル（「再生」「別パターン」「共有」等）
- 再生中は視覚的インジケータを表示
- 色だけに依存しない選択状態（チェックや太枠など）

### 8.6 空状態・エラー

| 状況 | 振る舞い |
|------|----------|
| 初回起動 | ホームで2択を強調。説明は短文1行まで |
| 生成失敗 | 再試行ボタン。技術詳細は折りたたみ |
| 書き出し失敗 | 権限・空き容量を平易に案内 |
| カタログ準備中 | 選択不可＋「準備中」 |

## 9. 非機能要件

| ID | 項目 | 要件 |
|----|------|------|
| N-01 | オフライン | 起動〜生成〜書き出しまでネットワーク不要 |
| N-02 | プライバシー | 音声・Intent・Recipe を外部送信しない。トラッキングは広告利用時のみ最小限 |
| N-03 | 性能（SE） | 典型 SE は 100ms 以内に再生開始（目安、実機で計測） |
| N-04 | 性能（BGM） | 32 秒相当の生成は数秒以内（目安） |
| N-05 | 安定性 | バックグラウンド移行時にクラッシュしない。長時間試聴でリークしない |
| N-06 | 対応 OS | 初期: iOS 17+（開発効率優先。必要なら 16+ に下げて再評価） |
| N-07 | 端末 | iPhone 実機必須で音質確認。シミュレータは機能確認用 |
| N-08 | テスト | Mapper とエンジンのユニットテスト（同一 Intent＋seed の回帰） |
| N-09 | カタログ整合 | UI に出す組み合わせと Mapper 対応表が一致していること（リストの単一ソース化を推奨） |

- 広告を入れる場合は ATT（App Tracking Transparency）方針を決定

## 14. リスクと対策

| リスク | 対策 |
|--------|------|
| 音が「おもちゃ」に聞こえる | プリセット調整と簡易マスタリングを早めに入れる |
| BGM メロディがランダム連打に聞こえる | MelodyComposer（モチーフ＋リズム型＋輪郭）。詳細は SOUND_PLAN |
| BGM のループ継ぎ目が目立つ | 小節単位設計＋クロスフェード書き出し |
| ジャンル追加が UI だけ先行する | 「選べる＝実装済み」ルールとカタログ単一ソース |
| 選択肢が多すぎて迷う | MVPは少数。グループ化。既定値を強くする |
| 開発が UI に偏りエンジンが育たない | Phase 1–2 で Mapper＋エンジンを先に固める。3.5 もエンジン中心 |
| ストアでAIアプリと誤認 | 手続き生成である旨を説明文・アプリ内に明記 |
| サンプル音源の権利 | 初期は合成のみ。追加時はライセンス表を必須化 |

## 15. 用語集

| 用語 | 意味 |
|------|------|
| 手続き的生成 | 乱数とルールで波形・音符を組み立てる方式。学習モデル必須ではない |
| Intent | ジャンル・シーン／用途・雰囲気・長さなど、ユーザーが選んだ制作意図 |
| Catalog | ジャンル／シーン／用途などの選択肢と、それに紐づく生成テンプレの定義集合 |
| Mapper | Intent を Recipe に変換する純ロジック |
| Recipe | エンジンが音を生成するために必要なパラメータ一式 |
| シード | 乱数の初期値。同じ Intent＋シードなら同じ結果を目指す |
| 別パターン | seed を変え、同じ意図のまま別バリエーションを生成する操作 |
| モチーフ | 反復・変奏の単位となる短いメロディ形（本製品ではおおむね2〜4小節） |
| MelodyComposer | Intent／Recipe からノート列を組み立てる純ロジック（予定） |
| ループBGM | 終端と始端が自然につながるよう設計された伴奏 |
| 微調整 | Intent 確定後に技術パラメータをいじる任意操作 |
